# AutoOC — автоматический подбор Core Clock Offset

**[Русский](AUTOOC.md) · [English](AUTOOC.en.md)**

AutoOC помогает подобрать смещение частоты ядра NVIDIA прямо во время майнинга. Майнер постепенно повышает Core Clock Offset, проверяет стабильность каждой карты и сохраняет найденное значение. При фиксированной частоте ядра это может снизить напряжение и потребление без снижения заданной частоты.

**AutoOC не разгоняет память и не управляет видеокартами AMD.** Для каждой NVIDIA-карты подбор идёт отдельно.

**Для PearlHash (PRL) рекомендуем фиксировать частоту памяти на 810 МГц** — на протестированных настройках это помогает повысить энергоэффективность. В HiveOS используйте **Lock Memory Clock**, в Windows — `--mclock 810`. Это отдельная настройка: AutoOC подбирает только смещение частоты ядра.

## Что требуется

- Версия N7Miner с AutoOC и флаг `--autooc`.
- **Залоченная частота ядра**: `Lock Core Clock` в HiveOS или `--cclock` в Windows. Если частота не зафиксирована, AutoOC пропускает карту.
- **Стартовый Core Clock Offset**: поле `Core Clock` в разгоне HiveOS либо `--coffset`. Если `--coffset` не указан, используется текущий offset карты.

В TUI рядом с `PearlHash` должна появиться надпись **AutoOC**, а в таблице видеокарт — столбцы `AUTO` и `CORE OC`.

## Как включить

### HiveOS

1. Для NVIDIA-карты укажите в разгоне **Lock Core Clock**, например `1800` МГц.
2. В поле **Core Clock** задайте стартовый offset, например `150` МГц. Для PRL рекомендуем также установить **Lock Memory Clock = 810 МГц** (если карта поддерживает такую фиксацию).
3. В полётном листе N7Miner, в **Extra config arguments**, добавьте:

~~~text
--autooc
~~~

4. Примените полётный лист и перезапустите майнер. В TUI проверьте надпись `AutoOC` и колонки `AUTO` / `CORE OC`.

### Windows (BAT)

Допишите флаги в команду запуска. Пример для одной карты (замените кошелёк):

~~~bat
n7miner.exe -a pearlhash -o prl-ru.kryptex.network:7048 -u YOUR_WALLET -w rig01 --cclock 1800 --coffset 150 --mclock 810 --autooc
~~~

`--cclock 1800` — фиксированная частота ядра, `--coffset 150` — начальное смещение. Для нескольких GPU поддерживаются списки значений через запятую.

## Как AutoOC подбирает частоту

| Этап | Что происходит |
| --- | --- |
| **Прогрев, 3 минуты** | После старта карта временно работает с offset на **20 МГц ниже** выбранного значения. Это уменьшает риск ошибки на холодной карте. |
| **Поиск** | Через каждые **20 минут стабильной работы** offset увеличивается на **10 МГц**. |
| **Проверка нового шага** | После повышения идёт 20-минутная проверка. Одна ошибка на этом этапе вызывает немедленный откат на 10 МГц. Неудачное значение становится потолком. |
| **Готово** | Когда достигнут максимум или найден потолок, AutoOC сохраняет результат и продолжает майнить с ним, в том числе после перезапусков. |
| **Ошибка после настройки** | Если на уже подобранном offset случатся **3 ошибки за 24 часа**, AutoOC снизит offset на 10 МГц и запомнит новый потолок. Ошибки старше суток больше не учитываются. |

**Границы:** вниз — не ниже начального offset −100 МГц. Вверх — не выше начального +150 МГц либо заданного `--autooc-max`. Подбор одной карты может занять несколько часов.

Время засчитывается только во время фактического майнинга. Паузы и отключения пула не ускоряют подбор.

### Пример отображения в TUI

~~~text
n7miner | PearlHash | AutoOC

GPU                       AUTO  CORE OC
RTX 3080                    ▲    +210
RTX 3080                    ✓    +180
RTX 3080                    ~    +190
RTX 3080                    ▼    +160
~~~

### Когда подбор закончен

Когда все карты достигли своих устойчивых значений, в колонке `AUTO` у каждой будет `✓`. Например:

~~~text
GPU                       AUTO  CORE OC
RTX 3080                    ✓    +230
RTX 3080                    ✓    +180
RTX 3080                    ✓    +210
RTX 3080                    ✓    +160
~~~

После перезапуска или ребута AutoOC использует сохранённые offsets: сначала проходит прогрев, затем карта возвращается к найденному значению.

### Значки в колонке AUTO

| Значок | Значение |
| --- | --- |
| `▲` | Идёт подбор или проверка нового шага. |
| `~` | Прогрев после запуска, временно пониженный offset. |
| `▼` | Offset недавно уменьшен из-за ошибок. |
| `✓` | Значение подобрано, поиск завершён. |
| `!` | Достигнут нижний предел, карта продолжает выдавать ошибки. Проверьте питание, райзер и память. |
| *Пусто* | AutoOC для карты выключен либо отсутствует фиксированная частота ядра. |

## Параметры командной строки

| Флаг | Назначение |
| --- | --- |
| `--autooc` | Включает подбор для подходящих NVIDIA-карт; по умолчанию выключен. |
| `--autooc-max 300` | Верхняя граница offset в МГц. Можно указывать значения по картам через запятую, например `300,250`. Без флага предел — стартовый offset +150 МГц. |
| `--autooc-warmup 3` | Прогрев после старта, в минутах (0–60). По умолчанию 3; `0` — без прогрева. |
| `--autooc-reset` | Сбросить сохранённый подбор для всех карт. |
| `--autooc-reset 0,2` | Сбросить подбор только для GPU 0 и 2. |
| `--cclock 1800` | Зафиксировать частоту ядра (в HiveOS можно использовать Lock Core Clock). |
| `--coffset 150` | Начальный offset. Если не указан, берётся текущий offset карты. |

## Где хранится результат

N7Miner сохраняет настройку в файл `n7miner-autooc.state`, отдельно для каждой видеокарты по её UUID.

- **HiveOS:** `/hive-config/n7miner-autooc.state` — сохраняется при перезапуске майнера, ребуте и обновлении.
- **Windows:** рядом с `n7miner.exe`. Если переносите майнер в другую папку, перенесите и этот файл.
- При добавлении новой карты поиск запускается для неё, а найденные значения остальных сохраняются.
- При изменении стартового offset или lock core clock в HiveOS для соответствующей карты подбор начинается заново **после перезапуска майнера**.

### Как начать подбор заново

Добавьте к запуску:

~~~text
--autooc --autooc-reset
~~~

Сброс срабатывает **один раз для заданного значения флага**: автоматические перезапуски не будут стирать результат постоянно. Для повторного сброса удалите флаг, один раз запустите майнер, затем добавьте его снова. Другой вариант — изменить выбор карт (например, с `all` на `0,2`).

Можно остановить майнер и вручную удалить файл `n7miner-autooc.state`, если нужен полный сброс.

## Ошибки и сообщения

AutoOC учитывает сбои GPU-ядра (в том числе CUDA 700 и 714–719, часто Xid 13/31) и зависания карты без завершённой работы, после которых watchdog перезапускает майнер. **Ошибки сети, пула и отклонённые шары не считаются ошибками AutoOC.**

Примеры строк журнала (иллюстративные):

~~~text
GPU0 autooc core offset +200 -> +210 MHz (20 min stable)
GPU3 autooc kernel fault 700 at core +170 MHz (2/3)
GPU3 autooc core offset +170 -> +160 MHz (3 kernel faults; ceiling +170)
GPU1 autooc counted a GPU hang (no completed work) at core +200 MHz
GPU0 autooc disabled: needs a locked core clock (--cclock or Hive OC core lock)
autooc reset: every card starts a new search
~~~

**Важно:**

- Во время подбора ошибка одной карты может перезапустить весь майнер. В первые часы это возможно.
- Нестабильный разгон памяти может выглядеть как ошибка ядра. Пока AutoOC ищет offset, лучше оставить запас по памяти.
- Если проблема была в райзере или питании, после её устранения вручную перезапустите подбор через `--autooc-reset` — найденный потолок сам по себе не повысится.
- Не меняйте разгон HiveOS на работающем майнере; после изменения перезапустите его.

## Данные для мониторинга

В `status.json` и в API `http://127.0.0.1:21550/api/v1/status` у каждой карты есть объект `autooc` либо `null`, когда функция для неё выключена.

Пример:

~~~json
"autooc": {
  "state": "capped",
  "base_mhz": 150,
  "target_mhz": 230,
  "ceiling_mhz": 240,
  "floor_mhz": 50,
  "max_mhz": 300,
  "faults": 0
}
~~~

Возможные состояния: `searching`, `warmup`, `probation`, `lowered`, `capped` (подбор завершён), `floor` (нижний предел).
